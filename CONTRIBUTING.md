# Contributing To Metis

Thank you for your interest in contributing to metis! This document provides guidelines and workflows to ensure high-quality, consistent contributions. Please read it thoroughly before opening issues or pull requests.

## Getting Started

**Prerequisites**

| Tool         | Minimum Version                    | Purpose                      |
| ------------ | ---------------------------------- | ---------------------------- |
| CMake        | 3.20                               | Build system                 |
| C++ Compiler | GCC 11 / Clang 14 / MSVC 2022 17.0 | Compilation                  |
| Git          | 2.30                               | Version control              |
| Python       | 3.9+                               | Optional: scripting, linting |


**Quick Setups**


```bash
# fork repo and clone
git clone https://github.com/USERNAME/metis.git

# create feature or branch to pull request
git checkout -b feature-update

# Configure and build
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DMETIS_ENABLE_SANITIZERS=ON -DMETIS_BUILD_TESTS=ON
cmake --build build --parallel

# running test
ctest --test-dir build --output-on-failure

# verify the binary works
./build/bin/metis --version
```

> [!TIP]
> Enable sanitizers (`-DMETIS_ENABLE_SANITIZERS=ON`) during development to catch memory errors and undefined behaviour

## Development Environment

**Recommended IDE Setup**

- `VS Code`: Install `C/C++` extension, `CMake` Tools, and `clangd`
- `CLion`: Import the project directly; `CMake` integration are automatically sync
- `Vim/Neovim`: Use `clangd` lsp with `compile_commands.json` (generated automatically in `build/`)


## Pre-commit hook (Optional but Recommended)

Install the project's own pre-commit hook to validate changes before push:

```bash
./build/bin/metis init --style google --enable-clang-tidy
./build/bin/metis install
```

This ensures your contributions pass clang-format, clang-tidy, and
trailing-whitespace checks before every commit.

## Coding Standard

**Language Standard**

- C++20 is required, use modern feature where the improve clarity:
    - `std::span` for non-owning array views
    - `Concepts` (`template <typename T> concept Parsable`) for type constraints
    - `std::ranges` algorithms
    - designated initializers (`Check{.name = "foo", .command = "bar"}`)

## Style Guide

| Rule          | Project Convention                                                                      |
| ------------- | --------------------------------------------------------------------------------------- |
| Naming        | `snake_case` for variables/functions, `PascalCase` for types, `kConstant` for constants |
| Namespaces    | `metis::application`, `metis::domain`, `metis::infrastructure`   |
| Headers       | `#ifndef METIS_MODULE_HPP` / `#define METIS_MODULE_HPP`                 |
| Line length   | 100 columns (enforced by `.clang-format`)                                               |
| Indentation   | 2 spaces                                                                                |
| Braces        | Attach style (`if (x) {`)                                                               |
| Private Member| Using `_` after declare member suffix, e.g `std::string name_;`                         |

**clang-format** configuration

The project uses the `.clang-format` generated by `metis init` (Google
style, 2-space indent, 100-column limit). Do not modify it without discussion.

```bash
clang-format -i $(git ls-files '*.cpp' '*.hpp' '*.cc' '*.h')
```

## Testing Requirements

> Untested code is broken code


**Writing Tests**


Using `Google Test` with the following conventions:

```cpp
// INFO: this example only
#include <gtest/gtest.h>

#include <filesystem>
#include <memory>

#include "metis/application/run_checks_use_case.hpp"
#include "metis/domain/config.hpp"
#include "metis/infrastructure/cli_git_repository.hpp"
#include "metis/infrastructure/os_file_system.hpp"
#include "metis/infrastructure/process_shell_executor.hpp"

using namespace metis;

// use fixture for setup / teardown
class RunChecksTest : public ::testing::Test {
 protected:
  void SetUp() override {
    // create temp dir, initialize git repo, etc
  }

  void TearDown() override {
    // clean up temp dir
  }
};

// test naming: UnitUnderTest_Scenario_ExpectedResult
TEST_F(RunChecksTest, Execute_EmptyConfig_ReturnsSuccess) {
  auto shell = std::make_unique<infrastructure::ProcessShellExecutor>();
  auto git_repo = std::make_unique<infrastructure::CliGitRepository>(
      std::make_unique<infrastructure::ProcessShellExecutor>());
  auto fs = std::make_unique<infrastructure::OsFileSystem>();
  application::RunChecksUseCase use_case(std::move(shell), std::move(git_repo), std::move(fs));

  domain::config::ProjectConfig cfg;
  cfg.project_name = "test";

  application::RunOptions opts;
  opts.source = application::FileSource::ALL_REPO;

  EXPECT_EQ(use_case.execute(cfg, opts), 0);
}
```

Tests live in `tests/` and are built into `build/bin/metis_tests`.
Pure string generators (`domain/config`, `generators/`) can be tested directly;
infrastructure-dependent paths are tested against temp git repos like the
fixtures in `tests/test_format_mode.cpp`.

**Running Tests**

```bash
# running test
ctest --test-dir build --output-on-failure

# run the test binary directly (verbose output)
./build/bin/metis_tests
```

## Commit Message

Using Conventional Commits to enable automated changelog generation

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

| Type       | Use When                                            |
| ---------- | --------------------------------------------------- |
| `feat`     | Adding a new feature                                |
| `fix`      | Fixing a bug                                        |
| `docs`     | Documentation-only changes                          |
| `style`    | Code style changes (formatting, semicolons, etc.)   |
| `refactor` | Code changes that neither fix bugs nor add features |
| `perf`     | Performance improvements                            |
| `test`     | Adding or correcting tests                          |
| `chore`    | Build process, dependencies, tooling                |
| `ci`       | CI/CD configuration changes                         |


```
feat(run): add --format flag for clang-format in-place formatting

Adds a new RunMode::FORMAT that triggers clang-format -i on eligible
files instead of running the full check suite. Includes file extension
filtering and git diff detection to report modified vs. clean files.

Closes #42
```
