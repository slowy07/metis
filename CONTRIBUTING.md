# Contributing To Sniffercommit

Thank you for your interest in contributing to sniffercommit! This document provides guidelines and workflows to ensure high-quality, consistent contributions. Please read it thoroughly before opening issues or pull requests.

## Getting Started

**Prerequisites**

| Tool         | Minimum Version                    | Purpose                      |
| ------------ | ---------------------------------- | ---------------------------- |
| CMake        | 3.20                               | Build system                 |
| C++ Compiler | GCC 11 / Clang 14 / MSVC 2022 17.0 | Compilation                  |
| Git          | 2.30                               | Version control              |
| Python       | 3.9+                               | Optional: scripting, linting |


**Quick Setups**


```bash
# fork repo and clone
git clone https://github.com/USERNAME/sniffercommit.git

# create feature or branch to pull request
git checkout -b feature-update

# Configure and build
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DSNIFFERCOMMIT_ENABLE_SANITIZERS=ON -DSNIFFERCOMMIT_BUILD_TEST=ON
cmake --build build --parallel

# running test
ctest --test-dir build --output-non-failure

# verify can checking on
# ./build/bin/sniffercommit --version
```

> [!TIP]
> Enable sanitizers (`-DSNIFFERCOMMIT_ENABLE_SANITIZERS=ON`) during development to catch memory errors and undefined behaviour

## Development Environment

**Recommended IDE Setup**

- `VS Code`: Install `C/C++` extension, `CMake` Tools, and `clangd`
- `CLion`: Import the project directly; `CMake` integration are automatically sync
- `Vim/Neovim`: Use `clangd` lsp with `compile_commands.json` (generated automatically in `build/`)


## Pre-commit hook (Optional but Recommended)

install project's own pre-commit hook to validate changes before push

```bash
./build/bin/sniffercommit init --style google --enable-clang-tidy
./build/bin/sniffercommit install
```

this make sure your contributions pass formatting and static analysis checks

## Coding Standard

**Language Standard**

- C++20 is required, use modern feature where the improve clarity:
    - `std::span` for non-owning array views
    - `Concepts` (`template <typename T> concept Parsable`) for type constraints
    - `std::ranges` algorithms
    - designated initializers (`Check{.name = "foo", .command = "bar"}`)

## Style Guide

| Rule          | Project Convention                                                                      |
| ------------- | --------------------------------------------------------------------------------------- |
| Naming        | `snake_case` for variables/functions, `PascalCase` for types, `kConstant` for constants |
| Namespaces    | `sniffercommit::domain` (e.g., `sniffercommit::project`, `sniffercommit::tooling`)      |
| Headers       | `#ifndef SNIFFERCOMMIT_MODULE_HPP` / `#define SNIFFERCOMMIT_MODULE_HPP`                 |
| Line length   | 100 columns (enforced by `.clang-format`)                                               |
| Indentation   | 2 spaces                                                                                |
| Braces        | Attach style (`if (x) {`)                                                               |
| Private Member| Using `_` after declare member suffix, e.g `std::string name_;`                         |

**clang-format** configuration


the project including `.clang-format` generated by `sniffercommit init`. this cannot modify without discussion.

```bash
clang-format -i src/*.cpp include/sniffercommit/*.hpp tests/*.cpp
```

## Testing Requirements

> Untested code is broken code


**Writting Test**


Using `Google Test` with following Convention

```cpp
// INFO: this example only
#include <gtest/gtest.h>
#include <filesystem>
#include "sniffercommit/executor.hpp"

namespace sniffercommit {

// use fixture for setup / teardown
class ExecutorTest : public ::testing::Test {
    protected:
        void SetUp() override {
            // create temporary dir, intialize git repo, etc
        }

        void TearDown() override {
            // clean up temporary dir
        }
};

// test naming: UnitUnderTest_Scnario_ExpectedResult
TEST_F(ExecutorTest, CollectFile_Staged_ReturnsOnly) {
    RunOptions opts {.source = FileSource::STAGED};
    auto files = collect_files(repo_root_, opts, {});
    EXPECT_FALSE(files.empty());
}

} // namespace sniffercommit
```

**Running Test**

```bash
# running test
ctest --test-dir build --output-on-failure

# with verbose output
./build/tests/sniffercommit_tests --gtest_also_run_disabled_tests
```

## Commit Message

Using Convetional Commits to enable automated changelog generation

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

| Type       | Use When                                            |
| ---------- | --------------------------------------------------- |
| `feat`     | Adding a new feature                                |
| `fix`      | Fixing a bug                                        |
| `docs`     | Documentation-only changes                          |
| `style`    | Code style changes (formatting, semicolons, etc.)   |
| `refactor` | Code changes that neither fix bugs nor add features |
| `perf`     | Performance improvements                            |
| `test`     | Adding or correcting tests                          |
| `chore`    | Build process, dependencies, tooling                |
| `ci`       | CI/CD configuration changes                         |


```
feat(executor): add --format flag for clang-format in-place formatting

Adds a new RunMode::FORMAT that triggers clang-format -i on eligible
files instead of running the full check suite. Includes file extension
filtering and git diff detection to report modified vs. clean files.

Closes #42
```
