# sniffercommit

**Fast, C++20-powered pre-commit hook and CI generator.**

sniffercommit is a static binary that replaces Python/Node-based pre-commit frameworks. It reads a TOML configuration file, generates a `.git/hooks/pre-commit` Bash script and/or a GitHub Actions workflow, and can also execute checks directly via the `run` subcommand. It is designed for C/C++ projects that need clang-format, trailing-whitespace detection, or any arbitrary command-based linter, with zero runtime dependencies beyond the operating system.

## Architecture Overview

sniffercommit follows a **domain-separated architecture** with independent modules organized by concern:

```
┌──────────────┐     ┌──────────┐     ┌──────────────────┐
│  argparse    │────▶│  main    │────▶│ config_manager   │
│  (CLI)       │     │(dispatch)│     │ (orchestrator)   │
└──────────────┘     └──────────┘     └───────┬──────────┘
                                              │
                    ┌─────────────────────────┼─────────────────────┐
                    │                         │                     │
              ┌─────▼──────┐          ┌───────▼───────┐    ┌───────▼───────┐
              │  project   │          │  precommit    │    │    cicd       │
              │  config    │          │  domain      │    │   domain      │
              │ (TOML)     │          │ (bash hook)   │    │ (GHA YAML)   │
              └─────┬──────┘          └───────────────┘    └───────────────┘
                    │
              ┌─────▼──────┐
              │  tooling   │
              │  config   │
              │(.clang-fmt)│
              └────────────┘

┌──────────────────────────────────────────────┐
│                 executor                      │
│  (file collection & check execution)          │
└──────────────────────────────────────────────┘
```

1. **`main.cpp`** parses CLI arguments via `argparse.hpp` (with `preparse_config_path()` for `--config`), determines the active subcommand, and dispatches to `ConfigManager` or directly to domain modules.
2. **`project_config.cpp`** loads/saves `.sniffercommit.toml` using `tomlplusplus`, populating a `project::ProjectConfig` struct. Also provides `generate_default()` for the `init` subcommand.
3. **`tooling_config.cpp`** manages `.clang-format` generation via `generate_clang_format()`, `.clang-tidy` generation via `generate_clang_tidy()`, and style parsing via `style_name()` / `parse_style()`. The formatter style is also consumed by `project_config` when constructing the `formatting` check command args.
4. **`config_manager.cpp`** orchestrates multi-step workflows: `initialize()` (init), `install()` (install), `load_project()`, `find_git_root()`.
5. **`precommit_domain.cpp`** generates a self-contained Bash pre-commit hook script via `generate_hook()`, validates its syntax with `bash -n`, and installs it to `.git/hooks/pre-commit`.
6. **`cicd_domain.cpp`** generates a GitHub Actions workflow YAML via `generate_github_actions()` and writes it to `.github/workflows/sniffercommit.yml`.
7. **`executor.cpp`** collects files from git (staged, all tracked, or explicit paths), filters by patterns and exclusion rules, then runs each configured check on matching files.

## Build System

### Requirements

- **CMake** ≥ 3.20
- **C++20** compiler (GCC ≥ 11, Clang ≥ 14, MSVC ≥ 2022 17.0)
- **Git** (for dependency fetching and commit embedding)

### Dependencies (fetched automatically via FetchContent)

| Dependency | Purpose | Version |
|------------|---------|---------|
| [tomlplusplus](https://github.com/marzer/tomlplusplus) | TOML config file parsing | v3.4.0 |
| [fmt](https://github.com/fmtlib/fmt) | Type-safe string formatting | 11.0.2 |

Both are fetched at configure time via `FetchContent_Declare` with `GIT_SHALLOW ON`. No system installation is required.

### Build Commands

```bash
# Release build
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel

# Debug build with sanitizers
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DSNIFFERCOMMIT_ENABLE_SANITIZERS=ON
cmake --build build --parallel
```

### CMake Options

| Option | Default | Description |
|--------|---------|-------------|
| `SNIFFERCOMMIT_ENABLE_SANITIZERS` | `OFF` | Enable AddressSanitizer + UndefinedBehaviorSanitizer (Debug only) |
| `SNIFFERCOMMIT_ENABLE_STATIC_LINK` | `OFF` | Link statically for a portable single binary |
| `SNIFFERCOMMIT_VERBOSE_CONFIG` | `ON` | Print platform/compiler summary at configure time |

### Compiler Warnings & Hardening

In GCC/Clang builds, the following warnings are enabled:
`-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Wshadow -Wnon-virtual-dtor -Wold-style-cast -Wcast-align -Wunused -Woverloaded-virtual -Wnull-dereference`

Plus hardening flags in non-Windows builds:
- `-Wl,-z,relro,-z,now` (RELRO + BIND_NOW)
- `-Wl,-z,noexecstack` (non-executable stack, Darwin excluded)
- `-fstack-protector-strong` (GCC only)

In MSVC builds:
`/W4 /permissive- /sdl /DYNAMICBASE /NXCOMPAT`

### Platform Detection

| `CMAKE_SYSTEM_NAME` | `SNIFFERCOMMIT_PLATFORM` | Define |
|---------------------|--------------------------|--------|
| `Linux` (no WSL) | `linux` | — |
| `Linux` (WSL) | `wsl` | `SNIFFERCOMMIT_PLATFORM_WSL` |
| `Darwin` | `macos` | `SNIFFERCOMMIT_PLATFORM_MACOS` |
| `Windows` | `windows` | `SNIFFERCOMMIT_PLATFORM_WINDOWS` |

### Build Metadata

During configuration, `cmake/config.hpp.in` is processed into `build/generated/sniffercommit/config_build.hpp`, embedding:
- Version string (from `CMakeLists.txt`)
- Platform (`linux`, `macos`, `windows`, `wsl`)
- Compiler ID and version
- Git commit hash (short)
- Build timestamp

These are accessible via `sniffercommit::BuildInfo`:

```cpp
struct BuildInfo {
  static constexpr const char *version = SNIFFERCOMMIT_VERSION;
  static constexpr const char *platform = SNIFFERCOMMIT_PLATFORM;
  static constexpr const char *compiler = SNIFFERCOMMIT_COMPILER;
  static constexpr const char *git_commit = SNIFFERCOMMIT_GIT_COMMIT;
  static constexpr const char *build_timestamp = SNIFFERCOMMIT_BUILD_TIMESTAMP;

  static void print(std::ostream &os);
};
```

The template file `cmake/config.hpp.in` uses CMake's `@ONLY` substitution:

```cpp
#define SNIFFERCOMMIT_VERSION "@SNIFFERCOMMIT_VERSION@"
#define SNIFFERCOMMIT_PLATFORM "@SNIFFERCOMMIT_PLATFORM@"
#define SNIFFERCOMMIT_COMPILER "@SNIFFERCOMMIT_COMPILER@"
#define SNIFFERCOMMIT_GIT_COMMIT "@SNIFFERCOMMIT_GIT_COMMIT@"
#define SNIFFERCOMMIT_BUILD_TIMESTAMP "@SNIFFERCOMMIT_BUILD_TIMESTAMP@"
```

### Static Linking

When `SNIFFERCOMMIT_ENABLE_STATIC_LINK=ON`, the binary uses static linking for a fully portable single binary (no shared library dependencies). This is Linux-only (not supported on Windows).

### Out-of-Source Build Enforcement

The CMakeLists.txt explicitly blocks in-source builds with a fatal error message if `CMAKE_SOURCE_DIR == CMAKE_BINARY_DIR`.

## Configuration Format

sniffercommit uses a TOML configuration file (default: `.sniffercommit.toml` in the current working directory).

### Schema

```toml
[project]
name = "my-project"

[[checks]]
name = "clang-format"
command = "clang-format"
args = ["-i", "--fallback-style=Google", "-style=file"]
patterns = ["*.cpp", "*.hpp", "*.h", "*.cc"]

[[checks]]
name = "trailing-whitespace"
command = "grep"
args = ["-E", "--text", "[[:space:]]+$"]
patterns = ["*"]

[exclude]
paths = ["build/", "third_party/", ".git/"]

[output]
local_hook = true
github_actions = false

[execution]
parallel = true
```

### Sections

| Section | Key | Type | Default | Description |
|---------|-----|------|---------|-------------|
| `[project]` | `name` | string | `"unnamed"` | Project name, embedded in generated scripts |
| `[[checks]]` | `name` | string | _required_ | Human-readable check name |
| `[[checks]]` | `command` | string | _required_ | Executable to run |
| `[[checks]]` | `args` | string[] | `[]` | Static arguments passed before the file path |
| `[[checks]]` | `patterns` | string[] | `[]` | Glob patterns to match files; `"*"` matches everything |
| `[exclude]` | `paths` | string[] | `[]` | Path prefixes to exclude from checks |
| `[output]` | `local_hook` | bool | `true` | Generate `.git/hooks/pre-commit` during `install` |
| `[output]` | `github_actions` | bool | `false` | Generate `.github/workflows/sniffercommit.yml` during `install` |
| `[execution]` | `parallel` | bool | `true` | Run checks concurrently (Bash background jobs) |

### Pattern Matching

sniffercommit supports a limited set of glob patterns in `executor.cpp::matches_pattern()`:

| Pattern | Semantics |
|---------|-----------|
| `*` | Matches every file |
| `*.cpp` | Matches any file ending with `.cpp` |
| `src/` | Prefix match — matches `src/foo.cpp`, `src/bar/baz.h` |
| `include/**` | Directory prefix — matches any path under `include/` |
| `**/suffix` | Suffix match — matches any path ending with `/suffix` |

Exclusion patterns in `is_excluded()` follow similar rules:
- `"build/"` — excludes any path starting with `build/` (trailing slash normalized)
- `"*.log"` — excludes files ending with `.log`
- `"third_party/"` — excludes the entire `third_party/` directory tree

### Validation Rules

When loading a configuration file, `project::load()` enforces these rules via `ProjectConfig::validate()`:

1. **Project name** cannot be empty.
2. At least one `[[checks]]` entry is required.
3. Every check must have a non-empty `command`.
4. Duplicate check names are rejected.

Validation errors throw `std::runtime_error` with a descriptive message. All validation is also available without exceptions via `ProjectConfig::is_valid()` and `ProjectConfig::validate()` returning an error string.

### TOML Parsing Edge Cases

The TOML parser (`project_config.cpp`) handles these edge cases gracefully via `toml++`:

- **Missing sections** — defaults apply (e.g., no `[output]` → `local_hook=true, github_actions=false`)
- **Empty arrays** — `checks = []` triggers validation failure ("at least one check required")
- **Unknown keys** — silently ignored (TOML spec behavior)
- **Type mismatches** — `toml++` returns `std::nullopt`, `.value_or()` uses the default
- **Missing file** — `std::runtime_error` with clear message
- **Parse errors** — `toml::parse_error` caught and re-thrown as `std::runtime_error`

### Subcommand Details

#### `init`

Creates both `.sniffercommit.toml` and `.clang-format` with sensible defaults in the current directory. The `clang-format` check in the generated TOML includes `--fallback-style=<style>` matching the chosen formatter style.

**Options:**

| Flag | Description |
|------|-------------|
| `--style <name>` | Formatter style: `google`, `llvm`, `chromium`, `mozilla`, `webkit`, `microsoft`, `gnu` (default: `google`) |
| `--name <name>` | Project name (default: current directory name) |
| `--indent-width <n>` | Indentation width for `.clang-format` (default: `2`) |
| `--column-limit <n>` | Column limit for `.clang-format` (default: `100`) |
| `--pointer-alignment <s>` | Pointer alignment style (default: `Left`) |
| `--brace-style <s>` | Brace placement style (default: `Attach`) |
| `--enable-clang-tidy`, `--tidy` | Enable clang-tidy static analysis check (generates `.clang-tidy`) |
| `--tidy-preset <name>` | Tidy check preset: `minimal`, `standard`, `strict`, `custom` (default: `standard`) |
| `--tidy-severity <s>` | Warnings-as-errors level: `note` (off), `warning` (compiler only), `error` (all) (default: `error`) |
| `--tidy-header-filter <0\|1\|2>` | Header filtering: `0`=none, `1`=project, `2`=all (default: `1`) |
| `--enable-cmake`, `--cmake` | Enable CMake scaffolding (generates `CMakeLists.txt` + `src/main.cpp`) |
| `--cmake-cpp-standard <n>` | C++ standard: `17`, `20`, `23` (default: `20`) |
| `--cmake-target-type <t>` | Build target: `executable`, `static`, `shared`, `header-only` (default: `executable`) |
| `--cmake-enable-testing` | Add testing infrastructure to generated `CMakeLists.txt` |
| `--cmake-enable-sanitizers` | Enable AddressSanitizer + UBSan in Debug builds |
| `--generate-src` | Generate `src/main.cpp` without CMake (implied by `--enable-cmake`) |

When `--enable-clang-tidy` is used, three files are created: `.sniffercommit.toml`, `.clang-format`, and `.clang-tidy` with the chosen preset.

Project name is auto-detected from the current working directory name if `--name` is not provided. Existing files are overwritten.

#### `install`

1. Generates a Bash pre-commit hook script (via `precommit::generate_hook()`).
2. Writes it to `.git/hooks/pre-commit` with executable permissions (Unix only).
3. Optionally generates a GitHub Actions workflow (via `generate_github_actions()`) and writes it to `.github/workflows/sniffercommit.yml`.

Requires a valid `.sniffercommit.toml` in the current directory.

#### `generate-gha`

Generates only the GitHub Actions workflow file (`.github/workflows/sniffercommit.yml`). Same semantics as `install` with `[output].local_hook = false`, but always writes regardless of the config's `github_actions` setting.

The generated workflow includes:
- Triggers on push and pull_request to all branches
- Concurrency group with `cancel-in-progress: true`
- `contents: read` permission
- 10-minute timeout
- `actions/checkout@v4` with `fetch-depth: 0`
- Conditional `clang-format` installation step (only if any check uses clang-format)
- Runs `./sniffercommit run --all-files --verbose` with `set -euo pipefail`

#### `run`

Executes checks directly from the binary (no generated script needed). Accepts the following flags:

| Flag | Description |
|------|-------------|
| `--all-files` | Run checks on all files tracked by git (via `git ls-files`) |
| `--verbose`, `-V` | Print detailed per-file execution output |
| `--dry-run`, `-n` | List files that would be checked without running checks |

**File source selection (mutually exclusive, listed in priority order):**

1. **Explicit files** — Positional arguments: `sniffercommit run src/main.cpp src/foo.cpp`
2. **`--all-files`** — All git-tracked files
3. **Default (no args)** — Staged files via `git diff --cached --name-only --diff-filter=ACM`

## Component Breakdown

### argparse.hpp — Templated CLI Argument Parser

**File:** `include/sniffercommit/argparse.hpp`

A **header-only, template-based** argument parser. No external dependency.

#### Key Design

- **`ArgParser` class** holds a list of `Option` structs, `Subcommand` structs, boolean flag stores, and an active subcommand string.
- **`add_option<T>()`** is a template method accepting a reference to a variable of type `T`. It stores a lambda that converts the CLI string value into `T` at parse time. The default value is converted to string for display in `--help`.
- **`add_flag()`** registers a boolean flag (no value argument).
- **`add_subcommand()`** registers a named subcommand with a description.
- **`parse()`** iterates `argv` once:
  1. Checks for `--help` and `--version`.
  2. If subcommands are registered, checks `argv[1]` for a matching subcommand name. If found, stores it and returns `true` immediately.
  3. Otherwise, iterates all args looking for registered options.

#### Type Constraints

The `Parsable` concept requires `std::assignable_from<T&, T>` and `std::default_initializable<T>`. Supported types: `std::string`, `int`, `bool`.

#### Known Limitation

Options (like `--config`) are defined globally, not per-subcommand. The `--config` option can only be parsed when no subcommand is present (e.g., `sniffercommit --config path.toml run` does not process `--config`). Use the default config path or run from the project root.

### project_config.hpp / project_config.cpp — Project Configuration

**Files:** `include/sniffercommit/project_config.hpp`, `src/project_config.cpp`

Namespace: `sniffercommit::project`

#### Data Structures

```cpp
struct Check {
  std::string name;
  std::string command;
  std::vector<std::string> args;
  std::vector<std::string> patterns;

  [[nodiscard]] std::string validate() const noexcept;
};

struct ProjectConfig {
  std::string project_name = "unnamed";
  std::vector<Check> checks;
  std::vector<std::string> exclude_paths;
  bool generate_local_hook = true;
  bool generate_gha = false;
  bool parallel = true;

  [[nodiscard]] std::string validate() const noexcept;
  [[nodiscard]] bool is_valid() const noexcept;
  [[nodiscard]] bool has_command(std::string_view cmd) const noexcept;
  [[nodiscard]] bool has_matching_checks(const std::string& file) const noexcept;
};
```

#### Loading Logic (`project::load()`)

1. Checks file existence.
2. Parses via `toml::parse_file()`.
3. Extracts each section using `toml++` table/array access with `.value_or()` defaults for safety.
4. Validates via `ProjectConfig::validate()`: each `[[checks]]` must have a non-empty `command`, at least one check must exist, and no duplicate check names.
5. Returns the populated `ProjectConfig` struct.

Error handling: throws `std::runtime_error` for missing files, parse errors, missing commands, empty check lists, or duplicate check names.

#### `project::save()` — TOML Serialization

Writes a `ProjectConfig` back to a TOML file using `fmt::format()`.

#### `project::generate_default()` — Default TOML Template

Generates a `.sniffercommit.toml` string populated with the project name and formatter style. The generated config includes:
- `clang-format` check with `--fallback-style=<style>`
- `trailing-whitespace` check via `grep`
- Default exclude paths: `build/`, `third_party/`, `.git/`
- `parallel = true` execution

### tooling_config.hpp / tooling_config.cpp — Tooling Configuration

**Files:** `include/sniffercommit/tooling_config.hpp`, `src/tooling_config.cpp`

Namespace: `sniffercommit::tooling`

Provides `.clang-format` generation and style parsing for the `init` subcommand.

#### Data Structures

```cpp
enum class FormatterStyle { Google, LLVM, Chromium, Mozilla, WebKit, Microsoft, GNU };

struct ClangFormatConfig {
  FormatterStyle style = FormatterStyle::Google;
  int indent_width = 2;
  int column_limit = 100;
  std::string pointer_alignment = "Left";
  std::string break_before_braces = "Attach";
  std::string standard = "c++20";
  bool sort_includes = true;
  bool reflow_comments = true;
  bool align_consecutive_assignments = false;

  [[nodiscard]] std::string validate() const noexcept;
};
```

#### `generate_clang_format()` — .clang-format Content

Produces a `.clang-format` YAML document string using all fields from `ClangFormatConfig`, including `BasedOnStyle`, `IndentWidth`, `ColumnLimit`, `PointerAlignment`, `BreakBeforeBraces`, `Standard`, `SortIncludes`, `ReflowComments`, and `AlignConsecutiveAssignments`.

#### `style_name()` / `parse_style()` — Style Conversion

- `style_name()` converts a `FormatterStyle` enum to its string representation (e.g., `FormatterStyle::LLVM` → `"LLVM"`).
- `parse_style()` parses a lowercased string (e.g., `"llvm"`) into the corresponding enum value. Throws `std::runtime_error` for unknown styles.

#### `generate_clang_tidy()` — .clang-tidy Content

Produces a `.clang-tidy` YAML document from a `ClangTidyConfig`. The preset selects a curated `Checks` list (see `preset_checks()`). Extra/exclude checks are appended with `+`/`-` prefixes. Key detail — `WarningsAsErrors` maps from `TidySeverity` to a glob pattern:

| `TidySeverity` | Generated `WarningsAsErrors` | Effect |
|----------------|-----------------------------|--------|
| `Note` | `''` (empty) | No warnings treated as errors |
| `Warning` | `'clang-diagnostic-*'` | Only compiler warnings as errors |
| `Error` | `'*'` | All clang-tidy warnings as errors |

The `header_filter_level` controls `HeaderFilterRegex`:

| Level | Generated value | Effect |
|-------|----------------|--------|
| `0` (none) | `""` | No header diagnostics shown |
| `1` (project, default) | `".*"` | All headers included in diagnostics |
| `2` (all) | `".*"` | Same as level 1 |

The template avoids invalid config keys (`Quiet` is CLI-only, never written to file) and uses PascalCase for all keys (`HeaderFilterRegex`, not `headerFilterRegex`).

#### `generate_cmake_lists()` — CMakeLists.txt Generation

Produces a full `CMakeLists.txt` document from a `CMakeConfig` struct. The generated CMake project includes:

| Feature | Condition | Output |
|---------|-----------|--------|
| Project declaration | always | `cmake_minimum_required(VERSION 3.20)`, `project()`, version, languages |
| C++ standard | always | `CMAKE_CXX_STANDARD`, `CMAKE_CXX_STANDARD_REQUIRED`, `CMAKE_CXX_EXTENSIONS` |
| Build type | always | Debug + Release configuration types |
| Compile commands | `export_compile_commands` | `CMAKE_EXPORT_COMPILE_COMMANDS` |
| Source files | always | Explicit `set(SOURCES ...)` list |
| Target | always | `add_executable()` / `add_library()` with sources, type, and include dirs |
| Compiler warnings | `enable_warnings` | `-Wall -Wextra -Wpedantic -Wconversion -Wshadow` (GCC/Clang) or `/W4` (MSVC) |

### precommit_domain.hpp / precommit_domain.cpp — Pre-commit Hook Domain

**Files:** `include/sniffercommit/precommit_domain.hpp`, `src/precommit_domain.cpp`

Namespace: `sniffercommit::precommit`

#### `generate_hook()` — Bash Pre-commit Script

Produces a POSIX-compatible Bash script with this structure:

```bash
#!/usr/bin/env bash
# Generated by sniffercommit v0.1.0 | DO NOT EDIT MANUALLY
# Execution mode: PARALLEL  (or SEQUENTIAL)
# Project: my-project
set -uo pipefail

FILES=$(git diff --cached --name-only --diff-filter=ACM | grep -vE 'exclude_pattern' || true)
```

The generated script includes three Bash functions:

1. **`filter_by_patterns()`** — Accepts a file list and glob patterns. Uses Bash-native `[[ $file == $pattern ]]` for matching.
2. **`run_check()`** — Iterates filtered files, runs the command on each, normalizes grep exit code 1, returns the aggregated status.
3. **Execution block** — depends on the `parallel` config setting:

**Parallel mode** (`parallel = true`):
```bash
declare -a PIDS=()
declare -A PID_TO_NAME=()

( run_check "clang-format" "clang-format" "-i" "--fallback-style=Google" "-style=file" "*.cpp" "*.hpp" ) &
PID=$!
PIDS+=($PID)
PID_TO_NAME[$PID]="clang-format"

( run_check "trailing-whitespace" "grep" "-E" "--text" "[[:space:]]+$" "*" ) &
PID=$!
PIDS+=($PID)
PID_TO_NAME[$PID]="trailing-whitespace"

# Wait loop with per-check error messages
if [[ ${#PIDS[@]} -gt 0 ]]; then
    EXIT_CODE=0
    for pid in "${PIDS[@]}"; do
        if ! wait "$pid"; then
            echo "[sniffercommit] [ERROR] ${PID_TO_NAME[$pid]} failed" >&2
            EXIT_CODE=1
        fi
    done
    exit $EXIT_CODE
fi
```

**Sequential mode** (`parallel = false`):
```bash
run_check "clang-format" "..." "..." "*.cpp" || EXIT_CODE=$?
run_check "trailing-whitespace" "..." "*" || EXIT_CODE=$?
exit $EXIT_CODE
```

#### `regex_escape()` — Path Escaping (static helper, not exported)

Despite being an internal helper, `regex_escape()` is critical for correct hook generation. It escapes regex-special characters in exclusion paths before embedding them in the `grep -vE` pattern. Characters escaped: `\ . + * ? [ ] ^ $ ( ) { } |`

For example, the exclude path `build/` becomes `build\/` in the regex, and `third_party/` becomes `third_party\/`.

#### `install()` — Hook File Writer

1. Creates `.git/hooks/` if absent (via `std::filesystem::create_directories`).
2. Writes `pre-commit` file with content (truncating existing file via `std::ios::trunc`).
3. Sets Unix permissions: `rwxr-xr-x` (owner all, group read+exec, others read+exec).
4. Returns `false` on file open failure.

#### `validate_syntax()` — Bash Syntax Validation

1. Writes the hook content to a temp file in the system temp directory.
2. Runs `bash -n <tempfile> 2>/dev/null` to check syntax.
3. Removes the temp file.
4. Returns `true` if syntax is valid, `false` otherwise.

Without this check, a bug in the hook generation could silently install a broken hook that fails at commit time.

#### `uninstall()` — Hook Removal

Removes `.git/hooks/pre-commit` if it exists. Returns `true` whether or not the file existed (idempotent).

#### `is_installed()` — Installation Check

Returns `true` if `.git/hooks/pre-commit` exists in the given repository root.

#### `initialize()` — Init Workflow

1. Determines project name (from `InitOptions` or current directory basename if name is empty).
2. Populates a `tooling::ClangFormatConfig` from init options (style, indent, column, pointer alignment, brace style).
3. Validates the clang-format config (`ClangFormatConfig::validate()` checks `IndentWidth` between 1–16 and `ColumnLimit` between 20–500).
4. Calls `project::generate_default(name, style_name)` or `generate_default_with_tidy()` → writes `.sniffercommit.toml` with the correct `--fallback-style=<style>` and optionally includes a `clang-tidy` check.
5. Calls `tooling::generate_clang_format(cfg)` → writes `.clang-format` with `BasedOnStyle` matching the chosen style.
6. If `opts.enable_clang_tidy`, calls `tooling::generate_clang_tidy(tidy_cfg)` → writes `.clang-tidy` with the selected preset and severity level.
7. If `opts.generate_source`, creates `src/` directory and writes `src/main.cpp` with a minimal `main()` stub.
8. If `opts.enable_cmake`, populates a `tooling::CMakeConfig` from init options (including `enable_clang_tidy` if clang-tidy was also enabled) and calls `tooling::generate_cmake_lists(cfg)` → writes `CMakeLists.txt` with build configuration, warnings, optional sanitizers/testing, and tooling integration.
9. Returns `InitResult` with all generated file paths. On any failure, returns `InitResult{success=false, error_message=...}`.

All public methods on `ConfigManager` are `static` — call them via `ConfigManager::method()` without instantiating the class.

#### `install()` — Install Workflow

All `ConfigManager` public methods are `static`. Callers should use `ConfigManager::install()` directly.

1. If `cfg.generate_local_hook`:
   - Calls `precommit::generate_hook(cfg)` to produce the Bash script.
   - Calls `precommit::validate_syntax(hook_content)` to verify the generated Bash is syntactically valid.
   - If valid, calls `precommit::install(repo_root, hook_content)` to write `.git/hooks/pre-commit`.
2. If `cfg.generate_gha`:
   - Calls `cicd::generate_github_actions(cfg, WorkflowConfig{})` to produce the YAML.
   - Calls `cicd::write_workflow(repo_root, wf_content)` to write `.github/workflows/sniffercommit.yml`.
3. Returns `InstallResult` with paths for whatever was actually installed.

Errors are surfaced through `InstallResult::error_message` — no exceptions thrown from this method.

#### `load_project()` — Config Loading

Simple delegation: `return project::load(path);`. Throws `std::runtime_error` if the file is missing or invalid.

#### `find_git_root()` — Repository Detection

Implements a two-tier fallback:

1. **Primary:** Runs `git rev-parse --show-toplevel 2>/dev/null` via `popen()`. If successful and the returned path exists, uses it.
2. **Fallback:** Walks up from `current_path()`, checking each parent for a `.git` directory.
3. Throws `std::runtime_error("Not inside a Git repository for git not in PATH")` if neither method succeeds.

This dual approach handles both standard repositories and submodules correctly (git rev-parse handles submodules; walking up handles detached worktrees).

#### `write_file()` (private)

Writes `std::string` content to a `std::filesystem::path` using `std::ofstream`. Returns `false` if the file cannot be opened. Used internally by `initialize()`.

#### `exec_cmd()` — Shell Command Execution

A thin wrapper around `popen(..., "r")` that reads stdout into a `std::string`. Used for git commands. Error: throws `std::runtime_error` if `popen` fails.

#### `shell_escape()` — Argument Escaping

Wraps a string in **single quotes** and escapes internal single quotes (`'\''`). Used when constructing shell command strings for `std::system()`.

#### `command_exists()` — PATH Check

Checks if a command is available in PATH using `command -v <cmd>`.

#### `matches_pattern()` — File Pattern Globbing

Implements a limited glob matcher:
- `"*"` → match all.
- `"*.ext"` → match files ending with `.ext`.
- `"dir/**"` → match files starting with `dir/` (anything under `dir/`).
- `"**/suffix"` → match files ending with `/suffix`.
- `"prefix"` → prefix match (matches `prefix/foo.cpp`).

#### `is_excluded()` — Exclusion Check

Checks if a file path starts with any excluded path prefix or matches `*.ext` exclusion patterns.

#### `collect_files()` — File Source Aggregation

- **STAGED:** Runs `git diff --cached --name-only --diff-filter=ACM` to get staged files.
- **ALL_REPO:** Runs `git ls-files` to get all tracked files.
- **EXPLICIT:** Converts user-provided paths to relative paths from the git root.

All sources filter through `is_excluded()`. Results are sorted and deduplicated.

#### `execute_checks()` — Check Runner

1. For each configured check, checks command availability via `command_exists()`.
2. Filters collected files by pattern.
3. Constructs a command string using `shell_escape()` with single-quote escaping.
4. Runs via `std::system()`, checking exit code via `WEXITSTATUS`.
5. Handles signal termination (WIFSIGNALED) for crash detection.
6. Special case: `grep`/`egrep`/`rg` exit code 1 is treated as success (no matches = linter passed).
7. Returns 0 if all checks pass, 1 otherwise.

Note: Despite `ProjectConfig::parallel`, the `run` subcommand always executes checks **sequentially** in the C++ binary. Parallel execution is only in the generated Bash hook.

## Design Decisions & Trade-offs

### Why a generated Bash hook instead of invoking the binary in the hook?

The generated Bash hook is self-contained — it does not require the sniffercommit binary to be installed on every developer machine or CI runner. A `git clone` + `sniffercommit install` is sufficient for setup. The trade-off is that the hook script contains generated logic that must be re-generated when the configuration changes.

### Why manual argv re-parsing for `run` flags?

`ArgParser::parse()` returns immediately after identifying a subcommand, without processing subcommand-specific options. This is a design limitation of the parser: options are global, not scoped to subcommands. The manual re-parse in the `run` block is a workaround. A future improvement would be to scope options per-subcommand.

### Why sequential execution in the binary but parallel in the hook?

The generated Bash hook uses `(...) &` background jobs for parallel execution, which is simple and reliable in a shell script. The C++ binary runs checks sequentially via `std::system()` because adding thread-based parallelism with proper output synchronization would increase complexity for limited benefit (the hook is the primary execution path; the `run` subcommand is for manual debugging).

### Why limited glob support?

sniffercommit only needs to support the patterns commonly used in pre-commit configurations: file extension filters and directory prefixes. Full glob expansion (e.g., `**`, `?`, `[a-z]`) is intentionally omitted to keep the matching logic simple and predictable.

### Why `popen()` for git commands instead of libgit2?

The project has zero runtime dependencies. Using `popen()` to shell out to `git` avoids linking against libgit2 or similar libraries, keeping the binary small and build times fast. The trade-off is reliance on `git` being in `PATH`.

### Why `std::system()` for check execution instead of `fork/exec`?

`std::system()` is portable and simple. For a developer tool where checks are linters that run in <1 second, the overhead of `fork/exec` vs. `std::system()` is negligible. The generated Bash hook uses direct command execution, not `std::system()`.

### Why does `init` generate a separate `.clang-format` alongside `.sniffercommit.toml`?

Some linters (notably `clang-format`) look for a `.clang-format` file in the project root to determine formatting rules. Generating both files from a single `init` command ensures that the `clang-format` check in the TOML (`--style=file` + `--fallback-style=<style>`) has a corresponding config file to read. Users get a consistent formatting setup without manual `.clang-format` creation.

### Why no subcommand-specific `--config` support?

The `--config` option is registered globally on the `ArgParser`. Because `parse()` returns early when a subcommand is found, options are not parsed when a subcommand is present. This means `sniffercommit run -c custom.toml` does not work — the `-c` is silently dropped. Fixing this requires either: (a) scoping options to subcommands in the parser, or (b) checking `--config` before all args. The codebase partially mitigates this with `preparse_config_path()`, which scans `argv` for `--config` before `ArgParser` processes arguments.

### Why domain-separated modules?

The project was refactored from monolithic files to domain-separated modules for better maintainability. Each domain (project config, tooling config, pre-commit, CI/CD) lives in its own pair of header/source files under its own namespace (`sniffercommit::project`, `sniffercommit::tooling`, `sniffercommit::precommit`, `sniffercommit::cicd`). The `ConfigManager` class orchestrates multi-step workflows (init, install), while domain modules remain independently testable and focused on a single responsibility.

## Error Handling Patterns

sniffercommit uses a consistent error handling strategy across all modules:

| Pattern | Where | Description |
|---------|-------|-------------|
| `std::runtime_error` throws | `project::load()`, `tooling::parse_style()`, `find_git_root()`, `cicd::generate_workflow()` | Fatal errors where the operation cannot continue. All caught by `main()`'s top-level try-catch. |
| Result structs with error strings | `ConfigManager::initialize()` / `install()` | Non-fatal or recoverable errors. Returns an `InitResult`/`InstallResult` with `success=false` and `error_message` populated. |
| `bool` return + early exit | `ArgParser::parse()`, `validate_syntax()` | Validation failures where the caller just needs pass/fail. |
| Stream-based warnings | `execute_checks()` | Non-fatal per-check failures (e.g., command not found) that don't abort the full run. |

The top-level `main()` wraps all dispatch in a single try-catch:

```cpp
try {
  // subcommand dispatch
} catch (const std::exception& error) {
  std::cerr << "[ERROR] " << error.what() << "\n";
  return 1;
} catch (...) {
  std::cerr << "[ERROR] Unknown fatal error occurred\n";
  return 1;
}
```

## Testing & CI

### Testing Approach

sniffercommit uses **end-to-end integration tests** rather than unit tests. Each test runs the built binary with various flags, inspects stdout/stderr for expected output, and verifies generated files (`.sniffercommit.toml`, `.clang-format`, `.clang-tidy`, hook scripts, workflow YAML) for correctness.

Tests are located in the `tests/` directory and are executed as:

```bash
# Run all integration tests
./tests/run_tests.sh

# Run a specific test
./tests/run_tests.sh test_init_basic
```

### Test Coverage

| Test | What it verifies |
|------|-----------------|
| `test_version` | `--version` outputs matching semver |
| `test_init_basic` | `init` creates `.sniffercommit.toml` + `.clang-format` |
| `test_init_with_tidy` | `init --enable-clang-tidy` also generates `.clang-tidy` |
| `test_install_hook` | `install` writes valid Bash hook, validates with `bash -n` |
| `test_generate_gha` | `generate-gha` writes `.github/workflows/sniffercommit.yml` |
| `test_run_dry_run` | `run --dry-run` lists files without executing checks |
| `test_run_explicit` | `run <file>` checks only the given file |
| `test_run_verbose` | `run --verbose` prints shell commands |
| `test_invalid_style` | `init --style invalid` exits non-zero with error message |
| `test_git_commit_hook` | Full flow: init → install → git add → git commit triggers hook |

### CI Pipeline

A GitHub Actions workflow (generated by `sniffercommit generate-gha`) runs on every push and pull request:

1. **Build** — cmake configure + build (Release and Debug)
2. **Lint** — `clang-tidy` with the project's own `.clang-tidy` config
3. **Test** — Integration test suite
4. **Package** — CPack DEB generation (Linux only)

## Build & Debug

### Debug Build with Sanitizers

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DSNIFFERCOMMIT_ENABLE_SANITIZERS=ON
cmake --build build --parallel
```

When `SNIFFERCOMMIT_DEBUG` is defined (automatically in Debug builds), debug output enables:

| Module | Debug Output |
|--------|-------------|
| `project_config.cpp` | Prints project name, check count, and parallel setting to stderr |

### Config Debug

```bash
# Enable verbose CMake output at configure time
cmake -B build -DSNIFFERCOMMIT_VERBOSE_CONFIG=ON

# This prints at configure time:
#   sniffercommit v0.1.0 - Config
#     Platform   : linux
#     Compiler   : gcc-14
#     Build Type : Debug
#     Git Commit : a8c3eb2
#     Sanitizers : ON
#     Static     : OFF
```

### Manual Hook Test

```bash
# Generate and install
./build/sniffercommit install

# Test the hook directly (outside git commit flow)
bash .git/hooks/pre-commit

# Inspect generated script
cat .git/hooks/pre-commit | less
```

### Direct Check Run (no hook needed)

```bash
# All tracked files
./build/sniffercommit run --all-files

# Specific files
./build/sniffercommit run src/main.cpp include/foo.hpp

# Dry-run (show what would be checked, no commands executed)
./build/sniffercommit run --dry-run --all-files
# Output: [DRY-RUN] Would check N file(s):
#   file1.cpp
#   file2.cpp

# Verbose output (print each shell command before execution)
./build/sniffercommit run --verbose src/main.cpp
# Output: $ 'clang-format' '-i' '--fallback-style=Google' '-style=file' 'src/main.cpp'
```

### Typical Workflow

```bash
# 1. Initialize a project
cd my-project
sniffercommit init --style google

# 2. Run checks before committing
echo "int main(){}" > main.cpp
sniffercommit run main.cpp

# 3. Install the hook for automatic checks
sniffercommit install

# 4. Commit
git add main.cpp
git commit -m "feat: initial"

# 5. (CI) Generate workflow (enable in config, then re-install)
sed -i '/^\[output\]/,/^\[/ s/github_actions = false/github_actions = true/' .sniffercommit.toml
sniffercommit install  # regenerates both hook and workflow
```
